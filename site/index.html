ControlSnack: Computer Use with any multimodal AI

Give a vision model a throwaway Linux desktop inside a sandbox on your computer. Watch it click, type and run commands. Stop it with one button, in milliseconds.

Get started in 5 steps New here? Guide with screenshots Every flag, documented

Pre-release. Run end to end on Windows 10 with hardware acceleration, with a local 4B model and with a hosted Qwen model, and on Linux in a VM; macOS has not been tried. Download it from the releases page; the programs are not signed.

What you get

Any model that can see

Point it at a model server you already run, or at a remote one: LM Studio, Ollama, llama.cpp, any OpenAI-compatible API such as OpenRouter, or Anthropic. A model that cannot see still works through the accessibility tree and the recognized text of the screen.

A sandbox, not a promise

The model works inside a QEMU virtual machine with no network device and nothing shared with your computer. Every action is checked against a policy and written to a tamper-evident log before it runs.

Yours alone

One program, no account, no cloud, no telemetry. The desktop is deleted when the session ends. The only thing that leaves your machine is what you send to the model you chose.

How it works

Four parts, each with one job. The model never touches your computer; it can only ask ControlSnack to act in the VM.

  1. Look. A screenshot, the accessibility tree and the recognized text of the screen go to the model.
  2. Decide. The model answers with actions: click, type, key, run a command, wait.
  3. Check. ControlSnack validates each action, applies the rules, asks you when a rule says so, and records the decision.
  4. Act. Only then does the action run in the VM, and its result goes back to the model.

  1. Install QEMU

    In PowerShell. Windows Home works: if the Hypervisor Platform is off, ControlSnack uses software emulation and says so.

    winget install SoftwareFreedomConservancy.QEMU

  2. Get ControlSnack

    Download the archive for your system: controlsnack_<version>_windows_amd64.zip. Unpack it where you saved it and go into the new folder.

    Expand-Archive .\controlsnack_v0.1.0-alpha.1_windows_amd64.zip -DestinationPath .
cd controlsnack_v0.1.0-alpha.1_windows_amd64

    The program is not signed, so Windows may say the publisher is unknown: choose More info, then Run anyway. The guide with screenshots shows every step.

    Or build from source. This needs Git and Go 1.26 or newer (winget install Git.Git and winget install GoLang.Go), and leaves the program in the dist folder, so use .\dist\controlsnack.exe below.

    git clone https://github.com/PacifAIst/controlsnack
cd controlsnack
go run ./tools/dev build

  3. Ask doctor

    It changes nothing and ends with the verdict a run would act on: will use whpx or will use tcg (slow).

    .\controlsnack.exe doctor

  4. Get the base image (once)

    Downloads Debian and builds the desktop, 10 to 40 minutes without hardware acceleration. Or import one built elsewhere with image import.

    .\controlsnack.exe image build

  5. Run

    Start a model server first (see Models), then:

    .\controlsnack.exe run --task "Open a terminal and print the kernel version"

Safety, in short

  • No network device. The guest cannot reach your network. --allow-net opens a bridge that refuses private and local addresses.
  • Nothing shared. No folders, no clipboard, no USB. Nothing the model does runs on your computer.
  • Every action judged first. Wiping the system, fork bombs, privilege escalation and the like are refused; deleting or overwriting asks you.
  • A log that cannot be quietly edited. Each record carries the hash of the one before; audit verify checks the chain.
  • Kill in milliseconds. The VM stopped 8 to 17 ms after the kill on Linux and about 120 to 140 ms on Windows in the tests, from the button, the keyboard or another terminal. If you walk away, the session pauses and ends.
  • What the screen says is data. Text from the guest is fenced and never taken as an instruction.

The command policy is a guardrail; the boundary is the VM. The README lists what it does not cover and the risks that remain.

    Questions

    Does my screen go anywhere?

    Only to the model you choose. With a model on your own machine (LM Studio, Ollama, llama.cpp) nothing leaves it. With a remote one, the screenshots, the accessibility tree and command output go to that provider, and the program says so when the session starts. There is no telemetry and no update check.

    Is Windows Home supported?

    Yes. ControlSnack uses the Windows Hypervisor Platform when QEMU can, and software emulation when it cannot, which works on every machine. Software emulation is several times slower: a desktop takes a minute or two to start.

    How do I stop it?

    The Kill button, Ctrl+Shift+Esc, Esc three times, controlsnack kill in another terminal, or Ctrl+C. Close the window and the session pauses after seconds and ends after a minute.

    Can the model damage my computer?

    It works inside a virtual machine with no network device and no shared folders, and its actions are checked before they run. The command rules are a guardrail, not a wall: the wall is the VM. The README says what is and is not covered.

    Where is every command and flag explained?

    In the documentation: every command, every flag with its default and its configuration key, the configuration file, the exit codes, the policy file, and the tools the model is given. If you are new, start with the guide: it goes from nothing to a first task, with a model on your own computer or through an API, with screenshots of the real program.

    What does it cost?

    Nothing. It is free software under the GNU Affero General Public License v3.0. A remote model costs what its provider charges.
